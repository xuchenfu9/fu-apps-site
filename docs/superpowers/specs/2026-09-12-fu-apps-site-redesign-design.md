# FU apps 官网视觉与响应式重设计

## 状态

待用户确认设计规格。确认后进入实现计划与代码改造。

## 背景

当前官网已经是 Astro 静态站点，包含八款应用、多语言目录、App Store 地区切换、应用详情页和隐私政策/用户支持/服务条款/营销条款页面。现有视觉更接近信息目录，产品主次、品牌识别和移动端阅读节奏不够突出。

本次改版参考独立 Apple 软件工作室的产品展示方式：Things/Cultured Code 的产品叙事层次、Tapbots 的多产品品牌体系、Panic 的极简产品分类、The Iconfactory 的作品集式展示。参考只用于提炼结构和原则，不复制其品牌、文案或视觉资产。

## 不可变约束

### 文档 URL 必须保持不变

以下现有路由是外部发布链接和 App Store 合规链接，改版不得修改、重命名或迁移：

- `/{locale}/apps/{slug}/privacy/`
- `/{locale}/apps/{slug}/support/`
- `/{locale}/apps/{slug}/terms/`
- `/{locale}/apps/{slug}/marketing/`（仅有营销条款的应用）

同时保持以下约定：

- 现有五种语言路径 `zh-Hans`、`zh-Hant`、`en`、`ja`、`ko` 不变。
- 八款应用的 slug 不变。
- `publicPath()`、`localePath()` 和 `DocumentNav` 继续作为内部链接的统一入口。
- 不修改现有法律文档正文、更新时间、联系方式或应用实际链接，除非用户另行提出内容更新。
- 文档页的返回应用、语言切换和同类文档导航必须继续工作。

### GitHub Pages 静态发布

- 保留 Astro 静态输出和现有 `.github/workflows/deploy-pages.yml`。
- 不引入数据库、登录、服务端 API、运行时渲染或必须依赖第三方服务器的交互。
- 动效使用 CSS 和少量已有客户端脚本；页面在 JavaScript 不可用时仍能阅读和打开文档链接。
- 继续使用本地 `public/assets` 素材，避免外部字体和不稳定的运行时资源。

## 目标信息架构

### 首页

1. 精简顶部导航：FU apps、应用列表、语言和 App Store 地区。
2. 首屏改为品牌 Hero：大标题、简短定位、查看应用入口和代表性应用视觉组合。
3. 增加重点应用展示区：优先展示已上架或最适合代表品牌的三款应用，以大图和主题色形成主次。
4. 增加全部应用区：其余应用使用紧凑但有辨识度的 Bento 卡片，继续显示版本号、上架状态和进入详情页入口。
5. 增加最近更新区：展示应用名、版本、更新摘要和详情页入口。
6. 保留页脚邮箱、语言入口和站点说明。

### 应用详情页

1. 采用大图 Hero：图标、应用名、定位、版本、App Store CTA 和第一张截图形成清晰首屏。
2. 用产品主题色区分不同应用，但保持统一的排版系统。
3. 将功能、截图、最近更新和应用文档组织为可快速扫描的区块。
4. 应用文档入口继续由 `DocumentNav` 输出，现有隐私政策、用户支持、服务条款和营销条款链接保持原 URL。

### 文档页

1. 保留现有 URL、文档正文和文档导航逻辑。
2. 只更新页面外壳、标题层级、阅读宽度、目录导航和移动端排版。
3. 文档页必须继续适合复制链接、浏览器返回和 App Store 审核使用。

## 视觉系统

- 基础色：深炭黑、暖米白、低饱和灰。
- 强调色：珊瑚、蓝色、绿色等应用主题色。
- 大标题使用 `clamp()` 响应式字号，避免固定尺寸导致手机溢出。
- 卡片使用较大的圆角、清晰边界和较少文字，截图成为主要视觉内容。
- 保留现有应用图标和截图，不重新生成或覆盖已批准素材。
- 使用 CSS hover/focus/transform 动效，并提供 `prefers-reduced-motion` 降级。

## 移动端要求

移动端是一级验收目标，至少覆盖 320px、375/390px 和 768px 宽度：

- 页面不得出现横向滚动或被截断的标题、按钮、卡片和截图。
- 顶部导航、语言切换和 App Store 地区选择在窄屏下能够折叠或换行，并保持可操作。
- 所有关键链接和按钮保持适合触控的尺寸，应用卡片整块可点击但 App Store CTA 仍可独立点击。
- Bento 卡片在窄屏下转换为单列或自然堆叠，不依赖 hover 才能理解内容。
- Hero、截图、版本信息、更新说明和文档入口按单列阅读顺序排列。
- 截图使用 `object-fit`、最大宽度和合理高度，避免撑破容器。
- 文档页正文宽度、行高、标题和导航适合手机连续阅读。
- 语言切换后仍保持当前应用和当前文档路径，不跳回首页。

## 实现边界

预计修改：

- `src/pages/[locale]/index.astro`
- `src/pages/[locale]/apps/[slug]/index.astro`
- `src/pages/[locale]/apps/[slug]/[document].astro` 的页面外壳结构（不改路由）
- `src/components/AppCard.astro`、`DocumentNav.astro`、必要的新展示组件
- `src/layouts/SiteLayout.astro`
- `src/styles/global.css`
- `src/lib/ui.ts` 中新增的界面标签
- `tests/e2e/site.spec.ts` 和必要的数据/路由测试

明确不修改：

- `src/data/legal/` 中的法律正文和更新时间
- 应用 slug、文档路由、语言路由和 App Store URL
- `public/assets/apps/` 中已批准的原始素材
- GitHub Pages 工作流的发布目标，除非验证发现必要的兼容性修复

## 验收标准

- 所有原有文档路由仍返回 200，并且链接目标与改版前完全一致。
- 首页和应用详情页在五种语言下都能构建。
- 320px、390px、768px 和桌面视口无横向溢出，关键操作可触控。
- App Store 地区切换、语言切换、应用卡片跳转、文档导航和返回路径继续正常。
- `npm test`、`npm run validate`、`npm run check`、`npm run build` 全部通过。
- Playwright 增加或保留桌面与手机视口验收，并覆盖隐私政策、用户支持、服务条款和营销条款路径。
- GitHub Pages Actions 能从 `main` 构建并发布静态产物。
